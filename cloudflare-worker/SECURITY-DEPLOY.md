# أ.٤ — تفعيل الصلاحيات على السيرفر (دليل النشر)

> **الكود جاهز ومُختبَر (١٢٧ فحص ناجح). الخطوات اللي تحت لازم تنفّذها إنت** لأنها محتاجة
> تسجيل دخول Cloudflare على حسابك — وأنا مالياش صلاحية عليه.
>
> ⚠️ **مهم جدًا:** نفّذ الخطوات **بالترتيب**. الوركر بيرفض الخدمة (503) لو مفيش مفاتيح
> متظبطة، فلو نشرت قبل ما تحط السيكرتس، النظام هيقف.

---

## ما قبل البدء — تحذير

المفتاح القديم `API_KEY` **لسه شغّال وبياخد صلاحية مدير**. ده مقصود، عشان الأجهزة
الشغّالة حاليًا في المحل ماتقعش لحظة النشر. **النظام مايبقاش مؤمَّن فعليًا غير بعد
الخطوة ٥** (مسح المفتاح القديم). متوقفش في النص.

---

## الخطوة ١ — ولّد ٣ مفاتيح قوية

نفّذ ده على جهازك. المفاتيح هتظهر على الشاشة عندك بس — **متكتبهاش في الشات ولا تبعتها
لحد في رسالة**.

```bash
# مفتاح المدير
echo "MANAGER: mgr_$(openssl rand -hex 24)"

# مفتاح الكاشير
echo "CASHIER: csh_$(openssl rand -hex 24)"

# رمز تصعيد الريفاند (٦ أرقام)
echo "REFUND_PIN: $(python3 -c 'import secrets; print(secrets.randbelow(900000)+100000)')"
```

على **ويندوز PowerShell**:

```powershell
# مفتاح المدير
"MANAGER: mgr_" + -join ((1..24) | ForEach-Object { '{0:x2}' -f (Get-Random -Max 256) })

# مفتاح الكاشير
"CASHIER: csh_" + -join ((1..24) | ForEach-Object { '{0:x2}' -f (Get-Random -Max 256) })

# رمز الريفاند
"REFUND_PIN: " + (Get-Random -Minimum 100000 -Maximum 999999)
```

احفظ التلاتة في مدير كلمات مرور. **لازم المفتاحين يكونوا مختلفين تمامًا** — لو حطيت
نفس القيمة للاتنين، كل الأجهزة هتبقى مدير والحل مايشتغلش.

---

## الخطوة ٢ — حُطّ السيكرتس على Cloudflare (قبل النشر)

```bash
cd cloudflare-worker
npx wrangler login          # لو مش مسجّل دخول
```

كل أمر هيسألك تلزق القيمة — الزق المفتاح المناسب واضغط Enter:

```bash
npx wrangler secret put MANAGER_API_KEY
npx wrangler secret put CASHIER_API_KEY
npx wrangler secret put REFUND_PIN
```

للتأكيد إن التلاتة موجودين:

```bash
npx wrangler secret list
```

المفروض تشوف `MANAGER_API_KEY` و`CASHIER_API_KEY` و`REFUND_PIN`، وكمان `API_KEY`
القديم (لسه موجود — عن قصد، هيتمسح في الخطوة ٥).

---

## الخطوة ٣ — شغّل الاختبارات ثم انشر

الاختبارات محتاجة Node 22.6+ أو 24+ ومحتاجاش أي تثبيت:

```bash
cd cloudflare-worker
npm test
```

المتوقع: `ALL 88 CHECKS PASSED` و`ALL 39 E2E CHECKS PASSED`. لو أي فحص فشل، **متنشرش**.

بعد نجاح الاختبارات:

```bash
npx wrangler deploy
```

---

## الخطوة ٤ — وزّع المفاتيح على الأجهزة

على **كل جهاز** في المحل: افتح النظام → **الإعدادات → المزامنة السحابية → مفاتيح المزامنة**.

| الجهاز | المفتاح اللي يتحط |
|---|---|
| كاشير / نقطة بيع | **مفتاح الكاشير فقط** — في خانة "مفتاح الكاشير" |
| جهاز المدير | **مفتاح المدير** — في خانة "مفتاح المدير" (تظهر لحساب المدير بس) |

⚠️ **متحطّش مفتاح المدير على جهاز كاشير مشترك.** أي متصفح فيه مفتاح المدير بياخد
صلاحية كاملة على السيرفر مهما كان المستخدم الداخل عليه.

ملاحظة: خانة مفتاح المدير مش بتظهر غير لما تكون داخل بحساب مدير — عشان الكاشير
مايرقّيش الجهاز بنفسه.

---

## الخطوة ٥ — 🔴 امسح المفتاح القديم (بدون الخطوة دي مفيش تأمين)

بعد ما تتأكد إن كل الأجهزة شغّالة بالمفاتيح الجديدة (سيبها يوم شغل كامل للاطمئنان):

```bash
cd cloudflare-worker
npx wrangler secret delete API_KEY
```

**قبل ما تمسحه، المفتاح القديم بيدي صلاحية مدير لأي حد عنده — يعني الثقب لسه مفتوح.**

طريقة تعرف إن لسه فيه أجهزة بتستخدمه: افتح لوج الوركر ودوّر على التحذير:

```bash
npx wrangler tail
```

لو شفت `DEPRECATED shared API_KEY` معناها لسه فيه جهاز محتاج تحديث — حدّثه الأول.

---

## الخطوة ٦ — تحقّق بنفسك إن الثقب اتقفل

ده اختبار القبول اللي في تقرير الفحص. حُط مفتاح الكاشير في `CASHIER_KEY`
و`WORKER_URL` بيتك:

```bash
CASHIER_KEY="csh_..."
WORKER_URL="https://system-online-backend.xxx.workers.dev"

# ١) كاشير يحاول يحذف أوردر → لازم 403
curl -i -X DELETE \
  -H "Authorization: Bearer $CASHIER_KEY" \
  "$WORKER_URL/v1/databases/default/collections/orders/documents/ANY_ID"

# ٢) كاشير يحاول يستبدل هاش باسورد المدير → لازم 403
curl -i -X PATCH \
  -H "Authorization: Bearer $CASHIER_KEY" \
  -H "Content-Type: application/json" \
  -d '{"data":{"key":"brewmaster_manager_creds_v1","value":"hacked"}}' \
  "$WORKER_URL/v1/databases/default/collections/settings/documents/global::brewmaster_manager_creds_v1"

# ٣) كاشير يحاول يعدّل سعر صنف في المنيو → لازم 403
curl -i -X POST \
  -H "Authorization: Bearer $CASHIER_KEY" \
  -H "Content-Type: application/json" \
  -d '{"documentId":"any","data":{"name":"x","price":1}}' \
  "$WORKER_URL/v1/databases/default/collections/menu/documents"

# ٤) كاشير يحاول ريفاند بدون رمز → لازم 403
curl -i -X PATCH \
  -H "Authorization: Bearer $CASHIER_KEY" \
  -H "Content-Type: application/json" \
  -d '{"data":{"refundedAt":"2026-01-01T00:00:00Z"}}' \
  "$WORKER_URL/v1/databases/default/collections/orders/documents/ANY_ID"

# ٥) كاشير يقرا الأوردرات → لازم 200 (الكاشير لازم يشتغل)
curl -i -H "Authorization: Bearer $CASHIER_KEY" \
  "$WORKER_URL/v1/databases/default/collections/orders/documents"
```

النتيجة الصح: **٤ ردود 403** وواحد **200**. لو أي واحدة من الأربعة رجعت 200، وقف
وراجع إن `wrangler secret list` فيها المفاتيح صح.

## خطة الرجوع (Rollback)

لو حصلت أي مشكلة بعد النشر:

**رجوع سريع (أسرع حل — دقيقة):**

```bash
cd cloudflare-worker
npx wrangler rollback
```

الأمر ده بيرجّع النسخة السابقة من الوركر فورًا. السيكرتس الجديدة مش بتتأثر
(الوركر القديم بيقرا `API_KEY` بس ومش بيعرف حاجة عن الجداد)، فالنظام يرجع
لسلوكه القديم على طول.

**لو محتاج ترجع من الجيت:**

```bash
git revert <commit-sha>
cd cloudflare-worker && npx wrangler deploy
```

**مهم:** **متمسحش** `API_KEY` (الخطوة ٥) غير بعد ما تتأكد إن كل حاجة مستقرة —
هو شبكة الأمان بتاعتك خلال فترة النقل.

## أعراض ومعانيها

| العَرَض | السبب | الحل |
|---|---|---|
| كل الطلبات 503 | مفيش أي سيكرت متظبط | نفّذ الخطوة ٢ |
| كل الطلبات 401 | المفتاح على الجهاز غلط | راجع الخطوة ٤ |
| الكاشير بيشوف "غير مسموح" في المزامنة | الجهاز عليه مفتاح كاشير وبيحاول عملية مدير | متوقع — أو حُط مفتاح المدير لو الجهاز جهاز مدير |
| الريفاند بيفشل عند الكاشير | رمز غلط أو `REFUND_PIN` مش متظبط | راجع الرمز، أو اعمل الريفاند من جهاز المدير |
| الريفاند بيفشل وإنت أوفلاين | رمز التصعيد بيتبعت في اللحظة بس (مش بيتخزّن على الجهاز عن قصد) | اعمل الريفاند وإنت أونلاين |
| صفوف "فاشلة" في حالة المزامنة | عمليات اترفضت بـ 403 | طبيعي — دوس "إعادة المحاولة" بعد تصحيح المفتاح |

## اللي المرحلة دي **مش** بتحلها (بصراحة)

عايزك تكون عارف السقف بالظبط:

**١. التوثيق لسه كلاينت-سايد.** الباسوردات بتتحقق في المتصفح
(`AuthContext` → `verifyManagerCredentials`)، والجلسة في `localStorage`، والتوكن
`token-${Date.now()}` مزيّف والوركر عمره ما بيشوفه. يعني المستخدم لسه يقدر يعدّل
`role` في DevTools ويفتح **شاشات** المدير في الواجهة.

الفرق المهم: بعد التعديل ده، الشاشات دي **مش هتقدر تعمل حاجة على السيرفر**. الحذف
٤٠٣، تعديل المنيو ٤٠٣، الإعدادات الحساسة ٤٠٣. اللي بيتخطى بقى واجهة فاضية،
مش صلاحية حقيقية.

**٢. قراءة هاشات الباسوردات لسه مسموحة للكاشير.** إجباري، لأن كل جهاز لازم
يقرا الهاشات من `settings` عشان اللوجين يشتغل أصلًا. اللي اتقفل هو **الكتابة**
عليها — وده اللي كان بيخلي الكاشير يبقى مدير. قراءة هاش PBKDF2 بـ ١٠٠ ألف تكرار
مش تصعيد صلاحيات.

**٣. "تقارير ❌" لسه في الـ routing.** التقارير محسوبة في المتصفح من `orders`،
والكاشير لازم يقرا الأوردرات لشاشة البيع. فمنع القراءة = منع الكاشير من الشغل.

### المرحلة ٢ — التوصية

لإغلاق التلاتة دول، لازم توثيق سيرفر-سايد كامل:

1. جدول `users` في D1 (id, username, password_hash, role)
2. `POST /v1/auth/login` على الوركر يتحقق ويرجّع جلسة موقّعة (HttpOnly cookie أو JWT)
3. الوركر يقرا الدور من الجلسة بدل ما يقراه من المفتاح
4. الهاشات تخرج من جدول `settings` خروج نهائي
5. `verifyManagerCredentials` تتحول لنداء شبكة

ده تغيير كبير ومحتاج تخطيط للأوفلاين (الكاشير لازم يشتغل وقت انقطاع النت)، فمتعمدين
تأجيله لمرحلة منفصلة.

## مرجع مصفوفة الصلاحيات (المطبَّقة فعلًا)

| العملية | كاشير | مدير |
|---|---|---|
| أوردر: إنشاء / تعديل / قبض | ✅ | ✅ |
| أوردر: تعديل مبالغ **بعد** القبض | ❌ | ✅ |
| ريفاند | ⚠️ برمز تصعيد (يتحقق على السيرفر) | ✅ |
| DELETE أي حاجة | ❌ | ✅ |
| حذف ناعم (`deletedAt`) | ❌ | ✅ |
| منيو / وصفات: كتابة | ❌ | ✅ |
| مخزون: إنشاء / حذف | ❌ | ✅ |
| مخزون: خصم/إرجاع بالبيع (`stock`) | ✅ | ✅ |
| مخزون: تكلفة / حد أدنى / اسم | ❌ | ✅ |
| إعدادات حساسة (كلمات مرور، PIN، ضريبة، بيانات المحل) | ❌ | ✅ |
| إعدادات الشيفت (لغة، طاولات، تصنيفات) | ✅ | ✅ |
| نسخ احتياطي (snapshots) | ❌ | ✅ |
| عملاء / شركات: إنشاء وتعديل | ✅ | ✅ |
| قراءة (GET) | ✅ | ✅ |

الملفات: القرارات كلها في `src/permissions.ts` (دوال نقية، قابلة للاختبار)، ونقطة
التطبيق الوحيدة `authorize()` في `src/index.ts` — بتتنادى قبل أي لمسة للداتابيز في
٥ مواضع (POST، PATCH، DELETE، و`/api/sync` بفرعيه).
